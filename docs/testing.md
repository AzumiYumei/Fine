# 下载改进验证记录

日期：2026-10-31（北京时间）

## 用户提供的 HLS 源

测试源域名：`hls.ohjzmm.cn`。不在仓库保存签名链接或解密密钥。

- 播放列表 HTTP 200，AES-128 加密，包含结束标记。
- 226 个 TS 分片，总时长 1126.375 秒。
- 密钥请求 HTTP 200，长度 16 字节。
- 桌面测试以 6 个线程完整获取 226/226 个分片，共 503,575,728 字节，耗时 34.51 秒；本次没有触发重试。
- 每个分片均通过 AES-CBC 解密、PKCS#7 填充及全部 188 字节 TS 包同步字节检查。
- 此结果验证当时的源可用性与数据结构，不代表 Android 手机上的实际速度，也不代表完成了音视频解码测试。

## 应用下载器回归测试

使用 Robolectric + 本地 MockWebServer，运行应用实际下载器和 Media3 缓存实现。通过 `./build.ps1` 执行。

最终结果：11 项测试全部通过（0 失败、0 跳过），压缩 APK 构建及签名校验通过；Android Lint 为 0 错误、2 条界面文字国际化提示。APK 大小 1,157,994 字节。

- 对一个分片持续返回 HTTP 503，检查总计四次请求，其余健康分片仍写入缓存；服务恢复后重试完成。
- 检查真实 HTTP 请求发生重叠，确认是分片并发而非串行下载。
- 丢弃失败分片后不再请求该资源；关闭服务器，仍能解析离线播放列表。
- 检查缺段标记、总时长、分片数量与隐式 AES IV 均保持正确。
- 同一文件的不同字节范围独立识别，丢弃其中一个不会误标其他范围。
- 检查丢弃状态跨对象重建保留、密钥不能丢弃、删除清空缓存及失败记录。
- 取消任务不被记作分片失败，工作线程能退出。
